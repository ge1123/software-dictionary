付款逾時，這筆可以再扣一次嗎？

Kill Bill 的 createPurchase 測試送出 10 AED，刻意讓模擬外掛比時限多等 100 毫秒。呼叫端收到 PAYMENT_PLUGIN_TIMEOUT。這個測試到此結束，沒有斷言扣款成功或失敗。看逾時測試

先找回原付款

這筆測試有兩個外部鍵。ohhhh 識別整筆付款，naaahhh 識別這次交易。處理這個案例時，可用前者查付款，再在傳回的交易中核對後者。查詢範例如下。查詢 API 的參數與回傳

GET /1.0/kb/payments?externalKey=ohhhh&withPluginInfo=true&withAttempts=true

Kill Bill 的背景查核工作用原付款 ID 向外掛取得交易清單，再用本地交易 ID 配對外掛的 kbTransactionPaymentId。若外掛查詢出錯或沒有相符交易，這次查核就缺少可確認的新結果。看交易配對與查詢失敗分支

查到什麼，能決定什麼？

原交易為 SUCCESS
成功的購買已有結果。再次以該交易外部鍵建立購買，交易鍵檢查會拒絕，回傳 PAYMENT_ACTIVE_TRANSACTION_KEY_EXISTS。看成功交易的重複鍵檢查
原交易仍是 UNKNOWN 或 PENDING
繼續查原交易。若試圖完成一筆仍為 UNKNOWN 的交易，處理器會拋出 PAYMENT_INVALID_OPERATION。PENDING 可以在多輪背景查核後仍維持原狀。看 UNKNOWN 的保護條件 · 看 PENDING 的排程測試
查到明確失敗
先核對失敗類型與正在執行的付款操作，再決定是否依該流程重試。Kill Bill 另有付款控制測試，先驗證 PLUGIN_FAILURE 和已處理金額為零，再以相同交易外部鍵重試。最後仍是一筆付款，有兩個交易紀錄，第一筆為 PLUGIN_FAILURE，第二筆為 SUCCESS。這個分支的起點是已確認的外掛失敗。看失敗交易與重試參數
查核能改變哪一筆紀錄？

另一個獨立測試先完成一次授權，再把原交易的本地狀態設為 UNKNOWN。測試推進時鐘，等候背景查核，重新讀取同一付款後，原授權交易恢復為 SUCCESS。這個斷言驗證的是授權狀態修正。前面 10 AED 購買的最終扣款結果仍未知。看授權交易的前後狀態
